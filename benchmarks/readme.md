# Benchmark results

## TL;DR
- Use `open` on fast drives
- Use `aio_uring` for high-IOPS workloads on Linux

## Benchmark Results: Disk I/O Performance

**Summary:**
- **Tested on:** Debian 12 (Linux 6.1.0-25-amd64)
- **Device:** Kinricun 128GB mSATA SSD (budget DRAM-less SSD)
- **Mode:** `O_DIRECT` where supported (bypasses page cache to measure raw device performance)
- **Test file:** 512 MB (bench_test.dat) generated by `benchmarks/read.py`

The benchmarks compare three approaches to file reads from cold cache:
- **Sync Blocking (standard)**: blocking reads via `os.read`/`readv`.
- **aiofiles (thread pool)**: uses a thread pool to emulate async reads.
- **io_uring (true async)**: uses asynchronous kernel IO via `aio_uring` bindings.

**Key Results** (median per-run values, across multiple runs):

| Metric | Sync Blocking | aiofiles (threads) | io_uring (async) | Notes |
| :--- | :---: | :---: | :---: | :--- |
| Throughput (Sequential 64KB) | 47.9 MB/s | 66.7 MB/s | **67.2 MB/s** (peak 84 MB/s) | io_uring median is ~40% faster than sync; peak throughput observed is ~75% higher |
| Latency (Sequential 64KB total time) | 10.70 s | 7.68 s | **7.62 s** | io_uring slightly improves total latency compared to blocking I/O |
| IOPS Stress (Sequential 4KB) | 42.39 s | 20.99 s | **7.71 s** | io_uring reduces overhead dramatically; shows best IOPS capacity |
| Random Access (10k seeks, 4KB) | 12.46 s | 19.85 s | **2.06 s** | io_uring is ~6x faster vs Sync, and ~10x vs aiofiles for this test |


## Hardware Reality Check

The tested device is a budget mSATA SSD. It's DRAM-less, so raw NAND performance is modest; the uplift we usually see on SATA/PCIe drives often relies on kernel & controller cache.

Key takeaways:
- The device is constrained by raw IO speed. Benchmarking while bypassing kernel caching removes the extra variability and highlights the software stack's overhead.
- The `io_uring` wins primarily by enabling parallelism (queue depth) and by overlapping user-land work and kernel IO.

## RAM Disk Benchmark Results (Lightspeed I/O)

To understand the true overhead of each approach without storage I/O bottlenecks, we tested all three methods on a **tmpfs RAM disk** (512 MB):
- **Tested on:** Linux 6.17.8-orbstack (aarch64) Python 3.12.12
- **Device:** In-memory tmpfs (RAM disk)

### Read Performance (RAM Disk)

| Test | Sync Blocking | aiofiles (threads) | io_uring (async) | Advantage |
| :--- | :---: | :---: | :---: | :--- |
| **Sequential 64KB (Throughput)** | **6735 MB/s** | 2437 MB/s | 6414 MB/s | io_uring: ~2.6x faster than aiofiles |
| **IOPS Stress 4KB** | **0.0692s** | 2.5299s | 0.3539s | io_uring: **7.1x faster** than aiofiles; ~5.1x slower than sync on median |
| **Random Read 10k seeks** | **0.0112s** | 0.3625s | 0.0462s | io_uring: **7.8x faster** than aiofiles; 4.1x slower than sync |

### Write Performance (RAM Disk)

**Buffered writes (64KB, no fsync):**

| Method | Median Time | Throughput |
| :--- | :---: | :---: |
| Sync Blocking | **0.0775s** | **6606 MB/s** |
| aiofiles | 0.3974s | 1288 MB/s (highly variable: 24–1900 MB/s) |
| **io_uring** | 0.1111s | 4607 MB/s |

**Durable writes (64KB + fsync):**

| Method | Median Time |
| :--- | :---: |
| Sync Blocking | **0.0009s** |
| aiofiles | 0.0092s |
| **io_uring** | 0.0023s |

**Direct writes (O_DIRECT/O_SYNC):**

| Method | Median Time |
| :--- | :---: |
| Sync Blocking | 0.0574s |
| io_uring | **0.0561s** |

## Analysis
On super-fast drives(more so on RAM disks), the overhead of threading and context switching in `aiofiles` becomes painfully obvious. The `io_uring` approach consistently outperforms `aiofiles` by a wide margin, especially in high-IOPS scenarios. However, regular blocking I/O still holds the edge in numerous cases.

---

## Recommendations and Practical Notes

- Avoid `aiofiles` when you need high-throughput or high-IOPS access on Linux.
- If your server uses cheap DRAM-less SSDs, consider enabling write-back or the kernel cache in production for better effective throughput.
- For workloads with many small random reads/writes, `io_uring` provides significant advantages. **Library is not yet production-ready, use with caution.**
